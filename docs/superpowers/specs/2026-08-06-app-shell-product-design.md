# 应用壳产品化（收敛设计系统展示）— 设计规格

- **日期**: 2026-08-06
- **状态**: 已确认（brainstorming 完成，待执行）
- **前置**: 设计规格 2026-08-05-app-shell-ui-design.md（应用壳，已并入 main）；2026-08-04-tauri-ui-design.md（设计系统基础）

## 1. 背景与目标

应用壳已完整落地（双模式入口、NavigationWheel 38.2% 参数化、双窗口级联、设置模式、FloatStrip、手机形态，已合并 main）。用户验收后提出产品化转向：

- **浏览器与 Tauri 形态一致**：浏览器 `/` 不再显示 docs 设计系统展示页，而是直接进入应用壳（与 Tauri 桌面同步）。
- **摒弃「设计系统展示」心智**：组件/令牌/动效/场景不是「给开发者看的展示区」，而是这个 UI 框架自身的组成部分，融合进应用壳的设置子菜单。
- 视觉完善：磨砂玻璃（非纯透明）、图标可读性、窗口控制功能、外观调整定位。

**四个核心决策**（brainstorming 确认）：
1. **玻璃质感**：磨砂玻璃（backdrop-filter 模糊 + 半透明）↔ **纯色不透明** 两档，默认磨砂；关闭后纯色实背景。浏览器侧用**装饰背景层**当模糊对象。
2. **窗口控制**：Tauri 真实三按钮 + 浏览器保留按钮+提示（toast「此功能在桌面端生效」），两端布局一致。
3. **图标增强**：提亮 + 高对比色、icon 衬底、选中态光晕分层、尺寸/粗细分级（四项全做）。
4. **外观调整**：重命名分组 + 整体实时预览；滑杆必须真正作用于全局（当前玻璃组滑杆在应用壳内无可见效果是缺陷）。

**实施分解**：B1 架构地基 → B2 视觉主体 → B3 设置完善（用户确认顺序）。

## 2. B1 架构地基（应用壳唯一产品形态）

### 2.1 模式系统重构

- `src/main.js`：删除 docs 分支。`?mode=app` / 无参数（浏览器 + Tauri）→ 应用壳；`?mode=strip` 保留（FloatStrip 独立入口）。
- `src/app/mode.js`：`resolveMode` 简化为 app/strip 两态；非法值回落 app。
- **删除**：`src/docs/docs-mode.js`、docs 独立骨架、docs 专属 CSS 全量加载（token-showcase/component-showcase/motion-lab/scenes/customizer 不再随主包加载）。

### 2.2 展示内容内化（设置子菜单重构）

设置目录从 8 分区扩为 **10 分区**（组件/动效为新增）：

| 分区 | 内容来源 | 说明 |
|---|---|---|
| 通用 | 现有通用 | 主题三态 / 动效开关 / 启动行为 |
| 外观 | 现有外观定制器 | = 视觉令牌的配置化表达（色彩/玻璃/排版/圆角/动效时长/阴影）；令牌区不再单设 |
| **组件** | 原组件矩阵 | 32 组件变体图鉴 + 剪贴板悬浮窗组合示例（场景模板演示价值保留于此） |
| **动效** | 原动效实验室 | 5 个演示卡 + 参数试玩器（与外观动效滑杆呼应） |
| 界面 | 现有界面 | 模块显隐开关 |
| 快捷键 | 现有快捷键 | HotkeyRecorder |
| 通知 | 现有通知占位 | — |
| 数据 | 现有数据占位 | — |
| 高级 | 现有高级占位 | — |
| 关于 | 现有关于 | 版本/许可 |

- **令牌区**：不单设，融进「外观」。
- **场景模板**：不单列——主窗口/设置页本身就是应用壳组成部分；剪贴板悬浮窗作为「组件」分区的组合示例。
- 组件/动效分区内容**按需加载**（Vite 代码分包），应用壳主包不拖展示内容。
- **B1 边界**：展示内容收进分区时宿主改造、样式沿用现有（玻璃/图标视觉升级归 B2）。

### 2.3 窗口控制双通道

- `window-controls.js` 扩展：Tauri 真实三按钮（现状已有）+ **浏览器降级**——按钮保留、点击 toast「此功能在桌面端生效」；拖拽区浏览器给轻量视觉反馈。两端布局一致。

### 2.4 测试/基线重构

- docs 专属 e2e（token-showcase/tokens/components-basic/motion-lab/scene-* 等）改造为「组件/动效」分区内验证；随 docs 页面移除而失去宿主的选择器用例删除。
- 视觉基线：docs 专属 36 张**删除**（tokens/components/scenes/main-window/settings-window/clipboard 中仅服务于 docs 页面的）；app-main 6 张**保留**；新增「组件/动效」分区基线（数量在 B1 计划中定）。
- 全量回归四项：`npm test` + `npm run test:e2e` + `npm run test:visual` + `npm run build`。

## 3. B2 视觉主体（玻璃材质体系 + 图标）

### 3.1 玻璃质感两档

- 应用壳导航栏/内容区/卡片从纯色 `--surface-1` 切换为玻璃材质（`.glass` 体系 + `backdrop-filter: blur(var(--glass-blur)) saturate(1.4)`，已有 base.css:19 基础）。
- 配置新增 `glass.blurEnabled`（磨砂开/关）：默认磨砂；关闭 → 纯色不透明实背景（浅色近白、深色近黑）。走配置链路（defaults → store → apply）。
- Tauri 侧：磨砂时窗口透明（模糊桌面壁纸）；关闭时窗口不透明（减少 GPU 合成）。
- 浏览器侧：应用壳根部加**装饰背景层**（柔和渐变/半透明几何色块/网格，随主题色联动）当模糊对象；Tauri 里该层可设透明，模糊真实壁纸。装饰背景层为可配置的纯 UI 态（会话内），提供 2-3 套预设（渐变/几何/网格）供切换。

### 3.2 图标增强（四项）

- 颜色：灰阶 `--text-3` → 高对比色（选中项强调色 + 未选中提亮），增大 stroke。
- 衬底：每个 icon 加圆角矩形/圆形衬底（hover/选中更明显）。
- 选中态光晕分层：现有 `c-navwheel__glow` 增强。
- 尺寸/粗细分级：非选中 20、选中 24 + 加粗 stroke。
- 影响组件：NavigationWheel、应用壳左/右窗纯图标栏。

## 4. B3 设置完善（外观调整定位）

- 外观滑杆回归「全局外观」本职：应用壳真用玻璃后，玻璃组滑杆（不透明度/模糊/高光）在壳内生效可见。
- 分组重命名（如色彩组 →「整体色调」、玻璃组 →「表面质感」）+ 实时整体预览图（缩略展示当前主题/玻璃/圆角/图标效果）。
- 语义：让「改的是整个 UI 而非字体」从文案和默认效果都明显。

## 5. 非目标（本期不做）

- 应用真实功能填充（剪贴板/密码/记账仍占位页）。
- Tauri 悬浮条独立窗口的 Rust 侧实现（仍靠 `?mode=strip` 入口 + 接入指南）。
- 多级联第三窗口（应用内深层级后续按需）。
- docs 设计系统展示页彻底删除后的历史参考恢复（拉 git 历史即可）。
